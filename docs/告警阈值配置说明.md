# 告警阈值配置系统

## 概述

告警阈值配置系统允许您为不同的检查项配置自定义的严重程度判断标准，替代原有的硬编码逻辑。

## 核心概念

### 1. 阈值方向（Threshold Direction）

- **upper（越高越严重）**: 如 CPU使用率、内存使用率、磁盘使用率
  - 值 > 严重阈值 → 严重（4级）
  - 值 > 错误阈值 → 错误（3级）
  - 值 > 警告阈值 → 警告（2级）
  - 值 ≤ 警告阈值 → 信息（1级）

- **lower（越低越严重）**: 如 缓冲命中率、可用空间
  - 值 < 严重阈值 → 严重（4级）
  - 值 < 错误阈值 → 错误（3级）
  - 值 < 警告阈值 → 警告（2级）
  - 值 ≥ 警告阈值 → 信息（1级）

- **range（偏离范围严重）**: 如 响应时间、温度
  - 需要配置 center（中心值）和 deviation（允许偏差）

- **exact（精确匹配）**: 如 状态码、错误类型
  - 使用字符串匹配规则

### 2. 配置优先级

```
客户 + 资产类型 > 客户 > 全局默认
```

- 最高优先级：特定客户 + 特定资产类型的配置
- 中等优先级：特定客户的配置（适用于所有资产类型）
- 最低优先级：全局默认配置（无客户、无资产类型）

### 3. 严重程度等级

| 级别 | 名称 | 图标 | 说明 |
|------|------|------|------|
| 1 | 信息 | ℹ️ | 一般信息通知，无需立即处理 |
| 2 | 警告 | 🟡 | 需要关注，可能影响性能 |
| 3 | 错误 | 🔴 | 需要尽快处理，已影响正常运行 |
| 4 | 严重 | 🚨 | 立即处理，服务可能中断 |

## API 接口

### 1. 获取可用检查项列表

```
GET /api/alerts/available-items/
GET /api/alerts/available-items/?protocol=mysql
```

### 2. 获取默认阈值配置建议

```
GET /api/alerts/default-thresholds/
GET /api/alerts/default-thresholds/?protocol=oracle
```

### 3. 创建阈值配置

```
POST /api/alerts/thresholds/

{
    "customer": 1,                    // 可选，客户ID
    "asset_type": 2,                  // 可选，资产类型ID
    "check_item_code": "CPU_USAGE",
    "check_item_name": "CPU使用率",
    "protocol": "ssh",
    "threshold_direction": "upper",
    "value_type": "percentage",
    "warning_threshold": "80",
    "error_threshold": "90",
    "critical_threshold": "95",
    "unit": "%",
    "description": "服务器CPU使用率阈值",
    "is_active": true
}
```

### 4. 查询阈值配置

```
GET /api/alerts/thresholds/
GET /api/alerts/thresholds/?customer=1&protocol=ssh
GET /api/alerts/thresholds/?check_item=CPU_USAGE
```

### 5. 测试阈值

```
POST /api/alerts/thresholds/{id}/test_value/
{
    "value": "85"
}

返回:
{
    "success": true,
    "value": "85",
    "severity": 2,
    "severity_name": "警告",
    "threshold_info": {...}
}
```

### 6. 批量检查

```
GET /api/alerts/thresholds/batch_check/?items=CPU_USAGE:85&items=MEM_USAGE:92&customer=1
```

### 7. 从模板创建

```
POST /api/alerts/threshold-templates/{id}/apply_to_customer/
{
    "customer_id": 1,
    "asset_type_id": 2  // 可选
}
```

## 使用流程

### 步骤 1：初始化模板

```bash
cd /path/to/ops-system
python scripts/init_threshold_templates.py
```

这将创建系统预定义的常用阈值模板。

### 步骤 2：执行迁移

```bash
python manage.py migrate alerts
```

### 步骤 3：配置阈值

**方式 A：从模板快速创建**

1. 获取模板列表：`GET /api/alerts/threshold-templates/`
2. 选择模板应用到客户：`POST /api/alerts/threshold-templates/{id}/apply_to_customer/`

**方式 B：手动创建**

1. 获取可用检查项：`GET /api/alerts/available-items/`
2. 获取默认建议：`GET /api/alerts/default-thresholds/`
3. 根据需求调整并创建：`POST /api/alerts/thresholds/`

### 步骤 4：验证配置

使用测试接口验证阈值是否按预期工作：

```bash
# 测试单个值
curl -X POST /api/alerts/thresholds/1/test_value/ \
  -H "Content-Type: application/json" \
  -d '{"value": "85"}'

# 批量测试
curl "/api/alerts/thresholds/batch_check/?items=CPU_USAGE:85&items=MEM_USAGE:92&customer=1"
```

## 配置示例

### 示例 1：为医院客户配置 Oracle 表空间阈值

```json
{
    "customer": 1,
    "asset_type": 3,
    "check_item_code": "TABLESPACE",
    "check_item_name": "表空间使用率",
    "protocol": "oracle",
    "threshold_direction": "upper",
    "value_type": "percentage",
    "warning_threshold": "75",
    "error_threshold": "85",
    "critical_threshold": "95",
    "unit": "%",
    "description": "医院Oracle数据库表空间使用率阈值（更严格）"
}
```

### 示例 2：为关键服务器配置更严格的 CPU 阈值

```json
{
    "customer": 1,
    "asset_type": 5,
    "check_item_code": "CPU_USAGE",
    "check_item_name": "CPU使用率",
    "protocol": "ssh",
    "threshold_direction": "upper",
    "value_type": "percentage",
    "warning_threshold": "70",
    "error_threshold": "85",
    "critical_threshold": "95",
    "unit": "%",
    "description": "核心业务服务器CPU使用率阈值"
}
```

### 示例 3：使用复杂规则

```json
{
    "customer": 1,
    "check_item_code": "ERROR_LOG",
    "check_item_name": "错误日志",
    "protocol": "mysql",
    "threshold_direction": "exact",
    "value_type": "string",
    "config": {
        "string_rules": {
            "critical": ["FATAL", "CRITICAL", "PANIC"],
            "error": ["ERROR", "Failed"],
            "warning": ["Warning", "Timeout"]
        }
    },
    "is_active": true
}
```

## 与巡检系统的集成

当巡检执行完成后，系统会：

1. 获取巡检结果（check_item_code 和 result_value）
2. 查找匹配的阈值配置（按优先级）
3. 根据阈值判断严重程度
4. 生成告警时包含阈值信息

**告警描述示例：**

```
## 检查项: CPU使用率

**检查结果**: 85%
**严重程度**: 警告 (2级)

**阈值配置**:
- 警告阈值: 80%
- 错误阈值: 90%
- 严重阈值: 95%
- 阈值方向: 越高越严重
```

## 注意事项

1. **向后兼容**: 如果没有配置阈值，系统会使用原有的硬编码逻辑（fail=错误，warning=警告）
2. **性能考虑**: 阈值查询使用了索引优化，不会影响巡检性能
3. **数据清理**: 删除客户或资产类型时，相关的阈值配置会自动清理
4. **模板管理**: 系统模板（is_system=true）不建议删除，可以禁用

## 数据库表结构

### alert_thresholds（告警阈值配置表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键 |
| customer_id | INT | 客户ID（NULL=全局） |
| asset_type_id | INT | 资产类型ID（NULL=所有类型） |
| check_item_code | VARCHAR(50) | 检查项编码 |
| check_item_name | VARCHAR(100) | 检查项名称 |
| protocol | VARCHAR(20) | 协议类型 |
| threshold_direction | VARCHAR(10) | 阈值方向 |
| value_type | VARCHAR(20) | 值类型 |
| warning_threshold | VARCHAR(100) | 警告阈值 |
| error_threshold | VARCHAR(100) | 错误阈值 |
| critical_threshold | VARCHAR(100) | 严重阈值 |
| unit | VARCHAR(20) | 单位 |
| config | JSON | 扩展配置 |
| is_active | BOOLEAN | 是否启用 |

### alert_threshold_rules（复杂阈值规则表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键 |
| threshold_id | INT | 阈值配置ID |
| severity | INT | 严重程度(1-4) |
| operator | VARCHAR(20) | 操作符 |
| threshold_value | VARCHAR(100) | 阈值 |
| sort_order | INT | 排序 |
| is_active | BOOLEAN | 是否启用 |

### alert_threshold_templates（阈值模板表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键 |
| name | VARCHAR(100) | 模板名称 |
| protocol | VARCHAR(20) | 协议类型 |
| check_item_code | VARCHAR(50) | 检查项编码 |
| check_item_name | VARCHAR(100) | 检查项名称 |
| default_config | JSON | 默认配置 |
| is_system | BOOLEAN | 是否系统模板 |
