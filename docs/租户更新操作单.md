# ops-system 租户端更新操作单

> **适用**：从任意旧版本（v31 / v35 / v37 / v38 / v39 均可）一次性升级到最新版
> **本次版本**：`2026-09-21-v40`（全量包）
> **预计耗时**：5～10 分钟
> **需要**：能 `sudo` 或 `systemctl` 重启后端服务的权限

---

## 〇、先看这次更新带来了什么

| 类别 | 内容 |
|---|---|
| **修复** | 驾驶舱「系统版本」长期显示过期版本（实际已是最新，界面却提示可更新） |
| **修复** | 补丁检查逻辑修正，只有确实存在新版本时才提示 |
| **同步** | 后端全部源码 + 前端构建产物一次性同步到最新（本次为「全量包」） |
| **数据库** | 附带 31 个历史迁移文件，用于补齐数据库结构 |

> 全量包说明：以往补丁只含当次改动的文件。若本机版本落后多个版本，
> 逐个补丁会漏文件，所以本次用全量包一次到位。

## 一、前置检查

```bash
# ① 确认在 ops-system 根目录（应看到 apply-patch.sh 和 backend/ frontend/）
cd /path/to/ops-system          # ← 改成你的实际路径
ls apply-patch.sh backend frontend

# ② 记下当前版本（后面要对比）
cat ~/.openclaw/patches/patch_version.txt

# ③ 确认能连通中心端（把地址换成系统设置里的「中心端地址」）
CENTER="http://works.beyondit.cn:18002"
curl -s -m 10 "$CENTER/api/collector/patches/" | head -c 200; echo
```

**期望**：能看到一段 JSON（含 `latest_version`）。若超时或报错，先解决网络问题，别往下走。

---

## 二、更新步骤（按顺序，别跳步）

> ⚠️ **本文所有 `python manage.py ...` 命令都必须先激活项目虚拟环境**
> （`cd backend && source venv/bin/activate`，见步骤 6）。直接敲 `python` 会用到系统
> Python，缺少项目依赖，报 `ModuleNotFoundError`。如果 `source venv/bin/activate` 报文件不存在，
> 说明项目用了别的方式管理依赖，请联系我方确认解释器路径。

### 步骤 1 — 先更新「更新脚本」本身

补丁包**覆盖不到** `apply-patch.sh` 自身，所以必须先从中心端拉最新的脚本
（本次同时修复了它「自动备份从未生效」的缺陷）：

```bash
cp apply-patch.sh apply-patch.sh.bak            # 留个旧版
curl -fsSL "$CENTER/api/collector/patches/?script=apply" -o apply-patch.sh
chmod +x apply-patch.sh
head -3 apply-patch.sh                          # 确认下载成功（应是 shell 脚本内容）
```

### 步骤 2 — 手工备份（双保险）

```bash
cp backend/config/settings.py /tmp/settings.py.bak
```

> 步骤 4 应用后会**自动备份**被覆盖的文件到 `~/.openclaw/patches/backup_<旧版本>/`，
> 这一步只是为了双重保险，成本 1 秒。

### 步骤 3 — 查看更新内容

```bash
./apply-patch.sh --check
```

**期望**：列出 7 条更新说明，不下载任何东西。

### 步骤 4 — 应用更新

```bash
./apply-patch.sh
# 提示「是否下载并应用此更新? [y/N]」时输入 y
```

**期望输出包含**：

```
发现新版本: <你的旧版本> → 2026-09-21-v40
下载完成 (1.1M)
✅ 已备份 257 个文件（保留目录结构）
  位置: ~/.openclaw/patches/backup_<你的旧版本>
正在应用补丁...
✅ 更新完成！
```

⚠️ **如果没看到「已备份 N 个文件」（N 是数字）**，说明步骤 1 的脚本没拉成功 —— 停手，
回到步骤 1 重新拉脚本，否则之后无法回滚。

### 步骤 5 — 核对数据库配置没被改

```bash
diff /tmp/settings.py.bak backend/config/settings.py
```

**期望**：只看到 `INSTALLED_APPS` 里多了 4 个应用（`discovery` / `skills` / `scheduler_v2` /
`lab_inventory`），**`DATABASES` 那几行与原来一致**。

若显示数据库地址/账号/密码被改动了 → 手工改回原值：

```bash
vi backend/config/settings.py     # 改回 DATABASES 段
```

### 步骤 6 — 执行数据库迁移

```bash
cd backend
source venv/bin/activate        # ← 必须！系统 python 不是项目环境
python manage.py migrate
```

**期望**：逐条打印 `Applying xxx...  OK`，最后 `OK`。若本来就齐全，会显示无操作。

### 步骤 7 — 执行数据初始化命令

（在步骤 6 激活了 venv 的**同一个终端**里继续执行）

```bash
python manage.py seed_time_sync_thresholds
```

**说明**：初始化「时间同步」告警阈值行。**可重复执行**（已存在的会打印「已存在，跳过」）。

### 步骤 8 — 重启后端服务

```bash
sudo systemctl restart beyondit-backend.service
# 如果你们的服务名不同，用下面之一：
#   sudo supervisorctl restart ops-system
#   sudo systemctl restart ops-system
```

```bash
# 确认起来了
sleep 3
systemctl is-active beyondit-backend.service      # 期望输出 active
```

### 步骤 9 — 浏览器强制刷新

前端构建产物本次有更新，请按 **Ctrl + F5**（或 Ctrl + Shift + R）强刷，
否则浏览器可能仍在用旧缓存。

## 四、异常处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `migrate` 报 **`table already exists`** | 该表以前手工建过，但迁移记录没写 | 记下应用名和迁移名，用 `python manage.py migrate <app> <迁移名> --fake` 跳过，然后继续跑 `migrate` |
| 步骤 4 没打印「已备份 N 个文件」 | 脚本没更新成功（仍是旧版） | 回到步骤 1 重新拉脚本，再重新执行步骤 2～4 |
| `curl` 拉脚本失败 / 404 | 中心端地址不对 | 到「系统设置」里核对「中心端地址」，注意端口 |
| `apply-patch.sh` 报「未检测到中心端地址」 | 系统设置里没配推送地址 | 改用 `./apply-patch.sh --url=http://中心端IP:端口` |
| `apply-patch.sh` 报「已是最新版本」 | 已经更新过了（幂等） | 无需处理；如需强制重装，先改 `patch_version.txt` 为旧版本号 |
| 界面还是旧版本 | 浏览器缓存 / 后端没重启 | Ctrl+F5 强刷；确认步骤 8 的服务已 `active` |
| 启动报 `RuntimeError: Model class ... isn't in an application in INSTALLED_APPS` | `settings.py` 没有更新成功（被手工改回旧版 / 覆盖失败） | 确认 `INSTALLED_APPS` 里有 `apps.discovery`、`apps.skills`、`apps.scheduler_v2`、`apps.lab_inventory` 四项 |
| 服务起不来且确认是本次更新导致 | — | 见下面「回滚」 |

## 五、回滚

被覆盖的原文件都在步骤 4 打印的那个目录里（保留完整目录结构）：

```bash
BK=~/.openclaw/patches/backup_<你的旧版本>
ls "$BK/backend" "$BK/frontend"            # 确认备份内容存在
ROOT=/path/to/ops-system                   # ← 改成你的实际路径

# 回滚后端与前端（备份保留了目录结构，直接覆盖回去）
cp -r "$BK/backend/."  "$ROOT/backend/"
cp -r "$BK/frontend/." "$ROOT/frontend/"

# 清掉字节码缓存，避免仍加载旧的 .pyc
find "$ROOT/backend" -type d -name __pycache__ -exec rm -rf {} + 2>/dev/null

# 恢复版本号（否则下次会以为已是最新）
echo "<你的旧版本>" > ~/.openclaw/patches/patch_version.txt

sudo systemctl restart beyondit-backend.service
```

> 若备份目录是空的，说明脚本没更新成功 —— 只能用步骤 2 手工备份的
> `settings.py` 恢复配置，代码回滚需要联系我方重新下发旧版包。
